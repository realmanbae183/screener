# 과매도 우량주 저가매수 봇 (Core)

미장(S&P500 + 나스닥100 + 다우30) 대상. 추세가 살아있는 우량주가
일시적으로 과매도 구간에 들어왔을 때만 후보로 올린다.
회전율이 낮고, 손절선보다 **진입 가격**으로 승부하는 구조.

## 설치 & 실행

```bash
pip install yfinance pandas numpy lxml
py run.py --setup          # 최초 1회: 유니버스 + 10년치 시세 (10~60분)
py run.py --status         # 데이터 보유 현황 확인
py run.py --repair         # 빠진 종목만 개별 재다운로드
py run.py                  # 일일 실행: 증분 갱신 후 스크리닝
py run.py --no-sync        # 저장된 데이터로만 (몇 초)
py run.py --no-sync --deep # ④악재 스크리닝까지 (후보 15종목, 1~2분 추가)

py test_indicators.py      # 지표 로직 검증 (18개 케이스)
py test_pipeline.py        # 파이프라인 통합 검증 (80종목 합성)
py test_fundamental.py     # ④단계 판정 검증 (18개 케이스)
```

실행이 끝나면 `report.html`이 생기고 브라우저가 자동으로 열린다.
`candidates.csv`도 같이 저장된다. 두 파일이 엑셀·브라우저에서 열려 있으면
이름 뒤에 시각을 붙여 따로 저장하므로 작업이 날아가지 않는다.

시세는 SQLite(`data/prices.db`)에 쌓인다. 차트 이미지가 아니라 OHLCV 숫자만
저장하고, 지표는 매번 여기서 계산한다. 최초 1회만 오래 걸리고 이후는 증분.

## 파이프라인

```
① 유니버스 필터    시총 100억$+, 바이오텍 제외, 히스토리 260봉+
        ↓
② 추세 필터        200일선 기울기 우상향 (or 종가가 200일선 -10% 이내)
        ↓          ★떨어지는 칼날 차단 — 이 봇의 생사를 가르는 단계
   냉각 기간        최근 10일 내 -10% 급락 있으면 대기
        ↓          EPS 추정치가 아직 안 고쳐졌을 시간을 준다
③ 과매도 스코어    7개 지표 / 17점 만점 / 10점 이상 통과
        ↓
④ 악재 스크리닝    EPS 개정 모멘텀 + 애널리스트 상하향 + GPM 추세
        ↓          + 실적 블랙아웃 + 기관 보유  →  A/B/C 등급
⑤ 13F 확인        (미구현) 추정 기관 평단 대비 위치, 순매수 방향
        ↓
⑥ 등급 + 사이징    A: 5%/-35%  B: 3%/-20%  C: 진입안함
```

## 과매도 지표 7종 (17점)

| 지표 | 조건 | 의미 | 배점 |
|---|---|---|---|
| ATR 이격도 | 20일선에서 2.5 ATR 이상 아래 | 종목별 변동성 대비 과했나 | 3 |
| 거래량 클라이맥스 | 평균 2배 투매 후 감소 | 팔 사람 다 팔았나 | 3 |
| MACD 강세 다이버전스 | 가격 신저점, MACD는 아님 | 하락 모멘텀 둔화 (선행) | 3 |
| RSI(14) | < 30 | 단기 매도 압력 소진 | 2 |
| 볼린저 %B | < 0 (하단 이탈) | 통계적 이상치 | 2 |
| 52주 낙폭 | -25% 이상 | 낙폭의 절대 크기 | 2 |
| 피보나치 되돌림 | 스윙 38.2~61.8% | 건전한 조정 범위 | 2 |

`ATR 이격도`가 최고 배점인 이유: "-30% 빠졌다"는 종목마다 의미가 다르다.
테슬라 -30%는 흔한 일이고 코카콜라 -30%는 사건이다. ATR로 나눠야
종목별로 공정하게 비교된다.

`MACD`는 골든크로스가 아니라 **다이버전스**를 본다. 골든크로스는 이미
반등이 시작된 뒤라 바닥 포착에는 늦다. 골든크로스는 나중에 실제
진입 트리거로 쓰면 된다.

## 구현 중 발견한 설계 이슈 (중요)

**1. 추세 필터와 과매도 필터는 서로 싸운다.**
우리가 노리는 -25~35% 낙폭은 거의 항상 200일선을 깬다. "종가 > 200일선"을
엄격히 요구하면 후보가 0개가 된다. 실제로 통합 테스트에서 통과한 25종목의
200일선 대비 위치는 전부 **-18~21%**였다. 그래서 종가 조건은 -10%까지
느슨하게 두고, 진짜 판정은 `200일선 자체가 아직 우상향인가`로 한다.
기울기 측정 구간도 60일로 길게 잡아야 우리가 사려는 그 급락에
기울기가 흔들려 조건이 뒤집히지 않는다. (`config.TREND_*`)

**2. 냉각 기간과 늘어짐 지표도 서로 싸운다.**
급락 후 10일을 기다리는 사이 20일선이 가격을 따라잡아서, 정작 평가
시점엔 이격도가 0에 가까워진다. 그래서 ATR 이격도·RSI·볼린저는
마지막 봉이 아니라 **최근 25봉의 극값**으로 판정한다. "지금 늘어져
있나"가 아니라 "최근에 그런 일이 있었나"를 묻는 것.
`SIGNAL_WINDOW > COOLING_DAYS + 급락 지속일` 조건을 반드시 유지할 것.

## ④ 악재 스크리닝 판정 규칙

핵심 질문은 하나다. **주가는 빠졌는데 미래 추정치는 그대로인가?**
그대로면 밸류에이션만 깎인 것(기회), 같이 빠졌으면 전망이 실제로 망가진 것(차단).

| 신호 | 기준 | 판정 |
|---|---|---|
| EPS 추정치 90일 개정 | ≤ -15% | **차단** — 전망 악화 |
| EPS 추정치 90일 개정 | -3% ~ -15% | 감점 — 구조적 침식 의심 (인텔 패턴) |
| EPS 추정치 90일 개정 | ±3% | 가점 — 밸류에이션만 조정 |
| 매출총이익률 | 3분기 연속 하락 | **차단** — 점유율 상실 (EPS 무관하게) |
| 실적발표일 | ±5일 이내 | **차단** — 컨센서스 미반영 구간 |
| 데이터 없음 | — | **확인불가(?)** — '문제 없음'으로 통과시키지 않는다 |

GPM을 독립 차단 사유로 둔 이유: 점유율 상실은 EPS보다 마진에 2~4분기 먼저
나타난다. EPS가 멀쩡해 보이는 구간에 계단식 하락을 사는 것을 막는다.
테스트의 `INTEL_PATTERN` 시나리오가 정확히 이 경우다 — EPS는 -7.3%로
감점에 그쳤지만 마진 3분기 연속 하락으로 차단된다.

데이터는 전부 yfinance 무료 범위에서 나온다(`eps_trend`, `eps_revisions`,
`quarterly_income_stmt`, `earnings_dates`, `institutional_holders`).
③단계를 통과한 소수 종목에만 조회하므로 500종목 재무를 미리 쌓아둘 필요가 없다.

## 다음 단계

1. **실데이터 검증** — `--setup` 돌려서 현재 시점에 실제로 몇 종목이
   걸리는지 확인. 너무 많으면 `SCORE_THRESHOLD`를 올리고, 0개면 내린다.
2. **백테스트** — 2008·2022 구간 필수 포함. ①②③만으로 MDD/CAGR 측정.
   ④⑤는 과거 컨센서스 스냅샷이 무료로 안 구해져서 백테스트 불가
   (look-ahead bias). 실전에서만 필터로 추가하고, 효과는 논리로만
   받아들이는 한계를 인정하고 간다.
3. **13F 파이프라인** — SEC EDGAR 파싱. XML 포맷이 연도마다 다르고
   CUSIP→티커 매핑이 필요해서 제일 지저분하다.

## 튜닝

모든 임계값은 `config.py`에만 있다. 백테스트하면서 여기 숫자만 바꾸면 된다.
특히 `SCORE_THRESHOLD`(현재 10), `TREND_MA_TOLERANCE`(0.90),
`ATR_DISTANCE_MIN`(2.5)이 후보 개수를 크게 좌우한다.
